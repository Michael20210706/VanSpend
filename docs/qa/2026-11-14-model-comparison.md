# 模型对比: gemini-2.5-flash 与 gemini-2.5-flash-lite(2026-11-14)

这是 2026-11-14 证据驱动优化轮的 H-M。线上用的是 `google/gemini-2.5-flash-lite`(`.env` 的 `OPENROUTER_MODEL` 覆盖了 `config/config.json` 的默认值 `google/gemini-2.5-flash`)。问题是换回默认的 flash 值不值。

每个结论后面标了 [测量]、[推断] 或 [猜测]。

## 结论(先看这里)

- **建议保持 flash-lite，不切换。** 验收规则的两条都不满足。本轮没有改 `.env`、`config/config.json` 或任何应用行为。
- 保留集整张全对: flash 4/12，flash-lite 3/12，差 +1，规则要求至少 +3。[测量，各 1 次]
- 每次扫描费用(保留集中位数): flash $0.001942，flash-lite $0.000356，比值 5.45 倍，规则要求不超过 2 倍。[测量，API 返回的 `usage.cost`]
- 费用这一条不是噪声。两个模型的标价决定了比值只能落在 3 倍到 6.25 倍之间，见"数字的解释"第 1 点。[推断，标价由 API 返回的分项费用反算]
- 真实 OpenRouter 调用 **49 次**，上限 120，计数文件 `eval/results/calls-models.json`。49 次的费用合计 $0.0776。[测量]

## 验收(H-M)

| 规则 | 数字 | 结果 |
|---|---|---|
| 保留集上 flash 的整张全对多至少 3 张 | flash 4/12，flash-lite 3/12，差 +1 | **不满足** |
| 每次扫描费用不超过 flash-lite 的 2 倍 | 中位数 $0.001942 对 $0.000356，5.45 倍(按均值 5.47 倍) | **不满足** |
| 结论 | | **建议保持 flash-lite** |

## 数字的解释(什么在限制它，它还可能量到了别的什么)

1. **费用为什么是 5.45 倍，为什么不可能降到 2 倍以内。** 每次调用的输入固定是 898 token(提示词加一张图)，输出中位数约 676 token。[测量] 由 API 返回的分项费用反算，flash-lite 是每百万 token 输入 $0.10、输出 $0.40，flash 是输入 $0.30、输出 $2.50。[测量，49 次调用里每个模型只出现这一组单价] 两个模型在保留集上的输出长度几乎相同(676 对 677)。所以比值由标价决定。输出为 0 时是 3 倍，输出无限长时趋近 6.25 倍。输出再短也到不了 3 倍以下，在现行标价下 2 倍这一条达不到。[推断]
2. **flash 的整张全对被什么卡住。** 合计税小票。保留集 2 张和首轮 4 张 tnt 小票，flash 全部在 gst、pst 上出错，而 gst+pst 之和都对。flash 会自己编一个拆分(例如把整笔税填进 gst，或拆成 2.33/0.48)，flash-lite 则填 0/0 或把整笔填进 pst。[测量，逐张看过原始输出] 现行 `normalize()` 的两条合计税规则只处理 gst 为 0 的形状，它们是 2026-11-11 和 11-12 照着 flash-lite 的输出写的。所以这次比较量到的是"模型加上为 flash-lite 调过的 normalize()"，对 flash 不利。[推断]
3. **如果不算拆分错误会怎样。** 事后加了一行敏感性指标，把"税拆错但之和对"也算对。保留集变成 flash 6/12 对 flash-lite 3/12，首轮变成 11/24 对 8/24。这一行是看过结果后加的，不参与验收，也没有据此改任何规则或提示词。即使按它算，准确率那一条刚好够 +3，费用那一条仍是 5.45 倍，结论不变。[测量，事后指标]
4. **两个模型共同的上限。** 小费行两边都是 0 提取(首轮 0/4，保留集 0/3)，带小费的小票一张都不可能全对。写法有歧义的日期(MM/DD)两边都常读反，保留集都是 1/3，首轮 flash-lite 5/7、flash 1/7。写法无歧义的日期两边一样(16/17、9/9)。[测量] 换模型解决不了这两类，H-R1 和 H-R2 处理的正是它们。
5. **flash 真正更好的地方。** 已匹配行的 taxable: flash 155/155 和 75/75，flash-lite 139/153 和 71/72。首轮集上两个区间不重叠(91% [85–94] 对 100% [98–100])，保留集上区间重叠(99% [93–100] 对 100% [95–100])。明细召回率在保留集上是 75/78 对 72/78。[测量，各 1 次]
6. **耗时。** 保留集上单次请求中位数 flash 3599 ms，flash-lite 2280 ms，慢 58%。[测量，各 12 次，同一小时内先后跑] 耗时与输出 token 数的相关系数是 0.86 到 0.99，所以限制耗时的是模型的生成速度(flash 约 200 token/秒，flash-lite 约 300 token/秒，按总耗时算，含首 token 等待)。[推断，没有单独测首 token 时间] 这些耗时是从开发机发出、并发 3 测的，不经过线上的 Tunnel 和服务器，绝对值不能当成线上的数字。
7. **排除的其他解释。** 没有失败或重试的调用(49/49 首次成功)。没有缓存命中(缓存 token 为 0)。没有跑错模型(回报的模型名与请求一致)。推理 token 为 0，所以 flash 的费用不是被默认开启的思考撑大的。[测量]

## 局限(必读)

- 保留集只有 12 张，每个模型各跑 1 次。3/12 的区间是 9–53%，4/12 的区间是 14–61%，几乎完全重叠。差 1 张不能说明谁更准。
- 保留集是合成图。它和首轮集共用同一个渲染器、同一套六类模板、同一套税规则和画面效果表，只换了种子、商家、商品和日期。它比首轮集"没被看过"，但不如真实手机照片独立。真实照片上的结果仍然没有证据。
- 保留集没有非小票图，没有长小票组，也没有 mixed-tax 组。
- flash-lite 在首轮 25 张上的数据是 2026-11-11 测的，没有 token、费用和模型名，耗时是含重试的整体耗时(那一轮 25 张都没有重试)。跨天的耗时不能直接比。
- flash 的运行间波动没有测。flash-lite 的 0/6 翻转只覆盖首轮集的 6 张图。
- `normalize()` 是照 flash-lite 的输出调的(见上面第 2 点)。在切换模型之前，这个偏差无法从本轮数据里去掉。
- 打分用的是本 worktree 的 `normalize()`。差额行和日期标记合并后，带小费小票的 consistent 和 tipFound 会变，需要重新打分。

## 怎么重跑

```bash
# 真实调用，会计费。只能通过 eval/run.cjs，上限写在环境变量里。已有成功结果的图会跳过。
export EVAL_HARD_CAP=120 EVAL_CALLS_FILE=eval/results/calls-models.json
node eval/run.cjs models-lite-holdout --dataset dataset-holdout.json --extra 0                                          # .env 里的线上模型，12 次
OPENROUTER_MODEL=google/gemini-2.5-flash node eval/run.cjs models-flash-holdout --dataset dataset-holdout.json --extra 0   # 12 次
OPENROUTER_MODEL=google/gemini-2.5-flash node eval/run.cjs models-flash-tuning --extra 0                                   # 25 次

# 零调用
node eval/models.cjs                                                              # 本文的全部表格和验收结论
node eval/replay.cjs models-lite-holdout models-flash-holdout models-flash-tuning # normalize() 变了之后的重放对比
npx vitest run --config eval/vitest.config.js                                     # 打分、保留集生成器、onMeta 钩子、验收判定的单测
```

命令行里的 `OPENROUTER_MODEL` 优先于 `.env`，`.env` 优先于 `config/config.json`(`src/openrouter.cjs` 只在环境变量为空时才用 `.env` 的值)。每张图的结果文件里有 `requestedModel`、API 回报的 `model` 和 `provider`、完整的 `usage`(含 `cost`)和 `apiMs`，格式与 `replay.cjs` 读的旧结果相同，只多了这几个字段。

## 范围边界

**已知的取舍与风险**
- 建议是按事先写好的规则给的。如果用户更看重 taxable 的准确率而不在意约 5.5 倍的单次费用(每次约多 $0.0016)，这条规则的结论可以推翻，那是费用上的决定。
- 费用比值随标价变。OpenRouter 或 Google 调价后要重算。

**严格约束**
- 没有改 `.env`、`config/config.json`、提示词或 `normalize()`。`scanReceipt` 只多了一个应用不传的可选钩子，返回结构不变(`tests/openrouter-meta.test.js`)。
- 测试不调用 OpenRouter。真实调用只经 `eval/run.cjs`，本轮 49 次，上限 120。

**本轮不包括**
- 没有为 flash 的输出形状补 `normalize()` 规则，也没有再跑第二轮。
- 没有测真实照片、第三个模型、带推理参数的 flash、或同一张图的多次运行。
- 没有测线上路径的耗时。
