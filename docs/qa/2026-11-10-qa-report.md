# VanSpend 线上系统全面测试报告(2026-11-10)

## 1. 目标、环境与方法
**目标**：在真实运行环境里，把系统的功能、权限、安全加固和运维做一次完整的黑盒检查，找出缺陷，并确认文档(`CLAUDE.md`)里写的规则在线上是否都成立。

**被测环境**：线上栈(compose 里的 `app` + 专用 `mysql:8.4.7` + `backup`)，公网入口 `https://www.vanspend.com/`(Cloudflare Tunnel)，同一个容器在本机 `http://127.0.0.1:3000`。部署的是 `main`(合并 #8 到 #18 之后)。当时库里只有测试数据，没有真实用户。

**入口约定**：所有需要登录、注册、输入密码的测试都打在 `127.0.0.1:3000`(与公网同一个容器、同一个数据库)；公网域名只做不带凭据、不改数据的 GET/HEAD 检查，以及(待补)由人工登录后的 cookie 检查。

**做法**：测试 agent 按区域分工，从外部(HTTP 与浏览器)把系统当黑盒测，期望行为以 `CLAUDE.md` 为准，文档没写的记为"观察项"，不硬判失败。每个区域都做正例、反例、边界、权限矩阵和小规模并发。

## 3. 已验证成立的关键规则(摘要)
- **权限**：所有管理接口对未登录/普通用户/管理员分别为 401/403/200；越权测试(含用 id 1 到 110 穷举)全部被拒；家庭可见性规则成立(加入前的个人小票对家庭不可见，离开或解散后立即看不到)；仅所有者能编辑小票。
- **限额与限速**：单 IP 每天 10 次、全站每天 60 次、开放档 3 次/天、正常档 20 次/天、开放档全站 150 次/天、登录锁与密码确认锁(10 次/15 分钟)全部与配置值一致，含边界、24 小时窗口和并发。
- **账号运维**：管理员重置密码、强制改密码门、自助注销(含创建者规则、图片清理)、审计日志(只记四类写操作、不记查看、不含临时密码、只读)全部符合文档。
- **安全加固**：安全响应头与 CSP 在本机和公网都在；CSP 实测拦下外部脚本、图片、iframe、fetch、ws；SQL 注入、原型污染、批量赋值无效；`.map`、`.env`、`.git` 取不到；日志里无密码、cookie、key；XSS 载荷在所有页面按文本显示。
- **运维**：应用和 MySQL 重启后数据完整，MySQL 重启后应用自动恢复；备份文件权限 600、`gzip` 校验通过、恢复到临时库与线上一致；应用只绑 `127.0.0.1:3000`、MySQL 只绑 `127.0.0.1:3307`，局域网不可达；公网伪造 `CF-Connecting-IP` 被 Cloudflare 拒绝；容器非 root；镜像里没有 `.env`、`.git`、`backups`。
- **并发**：家庭操作、账号注销、保存小票的混合并发(每类 8 到 12 轮)没有 5xx，一致性检查通过。

## 6. 没有覆盖到的部分(诚实清单)
- **公网域名上的所有"登录后"功能**：规则不允许在生产域名上由测试 agent 注册或输入密码，认证后的测试都打在同一个容器的本机入口。Cloudflare 对登录请求本身的影响，只靠第 7 节的人工 cookie 检查补充(HttpOnly 已确认，Secure/SameSite 只有间接证据)。
- **压力和长时间运行**：未做压力测试；备份服务的下一轮定时执行(24 小时)、真正进程崩溃时的自动重启都没有测到。
- **界面**：1440px 的管理后台只抽查；键盘焦点只测了一个弹窗；通过界面保存识别结果的流程只做了 1 次真实识别；超过 200 张小票时列表的截断没测。
- **识别模型整体准确率**：只用 8 张生成图片抽样。
- **家庭码被已解散家庭使用、过期码**等少数边角没测到。
- 部分结果来自测试 agent 的自述，我对其中几条做了独立复核(验证码 SVG 可读性)，其余未逐条重放。

## 7. 公网 cookie 检查(已由用户本人登录后完成)
用户本人在内置浏览器窗格里用公网域名完成了登录(我没有输入任何凭据)，之后只做了只读检查。

| 检查 | 结果 |
|---|---|
| 登录后在 `https://www.vanspend.com` 请求 `/api/auth/me` | 200，cookie 被正常带上 |
| 同一请求关闭凭据(对照) | 401 |
| 页面脚本能否读到会话 cookie `vanspend.sid` | **读不到**(`document.cookie` 里没有它)，符合 `HttpOnly` |
| 把页面换成 `http://` 再带凭据请求 | 请求失败，没有得到响应：浏览器因 HSTS 把这个主机强制升级到 HTTPS，所以**无法用这个办法直接证明 `Secure`** |

**结论与局限**：经 Cloudflare 的公网路径上，会话 cookie 能被 HTTPS 页面正常使用，且脚本读不到(HttpOnly 成立)；HSTS 在浏览器里生效。`Secure` 和 `SameSite=Lax` 没能在公网上由浏览器直接读出(浏览器不暴露 `Set-Cookie` 头)，只有间接证据：O 区域在本机(同一个容器)用 curl 读到的 `Set-Cookie` 带 `Secure; HttpOnly; SameSite=Lax`，容器环境 `COOKIE_SECURE=true`，Cloudflare 一般不改写这些属性。若要定论，可在浏览器开发者工具的"应用 → Cookie"里确认 `vanspend.sid` 的这几列。
